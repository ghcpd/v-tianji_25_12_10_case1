## 🐞 Bugs found and fixes applied

1. debouncedSearch — incorrect implementation
   - Problem: The exported `debouncedSearch` returned a debounced wrapper that ignored the requested delay and didn’t expose a reusable debounced function.
   - Fix: Make `debouncedSearch` a factory that returns `debounce(callback, delay)`.
   - File: helpers.ts (function replaced)

2. truncateText — incorrect / unsafe truncation for small maxLength
   - Problem: For small `maxLength` values (<=3), the calculation had a negative or otherwise incorrect substring range.
   - Fix: Return an empty string for non-positive lengths; if `maxLength <= 3` slice up to `maxLength` then append `'...'`; otherwise keep space for 3-character ellipsis.
   - File: helpers.ts

3. groupBy — grouping treated falsy keys (0, '') as 'undefined'
   - Problem: Using `item[key] || 'undefined'` converted 0 and '' into `'undefined'`.
   - Fix: Check explicitly for `null`/`undefined` and otherwise use `String(keyVal)`.
   - File: helpers.ts

4. deepClone — fragile property check and array handling
   - Problem: Relied on `obj.hasOwnProperty` (which fails for objects with no prototype) and used `instanceof Array`.
   - Fix: Use `Object.prototype.hasOwnProperty.call(...)` and `Array.isArray(...)` for robust handling. Proper date cloning kept.
   - File: helpers.ts

5. throttle — double call bug on first call
   - Problem: The implementation stored `lastArgs` for every invocation — including the first call — causing duplicate execution (immediate + trailing) when there were no subsequent calls.
   - Fix: Only store `lastArgs` when the throttle is active (i.e., already throttled). This preserves expected immediate + optional trailing behavior without double-calling on single call.
   - File: helpers.ts
